# Сервисы

Бизнес-логика: управление пользователями, картами и переводами.

## Классы

### UserService

Сервис для работы с пользователями.

**Основные методы:**

1. `register(RegisterRequest request)` - регистрация нового пользователя

2. `getCurrUser()` - получение текущего аутентифицированного пользователя

3. `getUserById(Long id)` - получение пользователя по ID

4. `getAllUsers(Pageable pageable)` - получение всех пользователей с пагинацией (только для ADMIN)

5. `updateUserRole(Long userId, Set<RoleName> roles)` - обновление ролей пользователя (только для ADMIN)

6. `getUserByEmail(String email)` - поиск пользователя по email (только для ADMIN)

**Проверки:**

1. Уникальность username и email при регистрации

2. Права доступа для административных методов

3. Существование пользователя перед операциями

### CardService

Сервис для работы с банковскими картами.

**Основные методы **(для пользователя)**:**

`getCards(Pageable pageable)` - получение всех карт текущего пользователя

`getCardById(Long cardId)` - получение карты по ID

`getCardBalance(Long cardId)` - получение баланса карты

`blockCard(Long cardId)` - блокировка своей карты

`getCardsByStatus(CardStatus status)` - получение карт по статусу

`getCardByIdAndUser(Long cardId)` - получение карты с проверкой принадлежности

`getCardBalanceIfOwner(Long cardId)` - получение баланса с проверкой принадлежности

**Основные методы **(для администратора)**:**

1. `getAllCardsA(Long userId, CardStatus status, String owner, Pageable pageable)` - получение всех карт с фильтрацией

2. `createCard(CardRequest request, Long userId)` - создание карты для пользователя

3. `activateCard(Long cardId)` - активация карты

4. `deleteCard(Long cardId)` - удаление карты

**Проверки:**

1. Принадлежность карты пользователю

2. Статус карты при операциях

3. Уникальность номера карты

4. Права доступа для административных методов

### TransferService

Сервис для переводов между картами.

**Основные методы:**

1. `transfer(TransferRequest request)` - перевод средств между картами

**Логика перевода:**

1. Валидация суммы перевода

2. Проверка существования обеих карт

3. Проверка принадлежности карт текущему пользователю

4. Проверка статуса карт (обе должны быть `ACTIVE`)

5. Проверка достаточности средств

6. Списание с карты отправителя

7. Зачисление на карту получателя

Сохранение изменений

Проверки:

1. Сумма перевода должна быть положительной

2. Карты должны принадлежать одному пользователю

3. Карты должны быть активны

4. Достаточно средств для перевода

### AdminService
Сервис для административных функций.

**Основные методы:**

1. `makeAdmin(Long userId)` - назначение пользователя администратором

2. `deactivateUser(Long userId)` - деактивация пользователя (удаление всех ролей)

3. `getTotalUsers()` - получение общего количества пользователей

**Проверки:**

1. Текущий пользователь должен иметь роль ADMIN

2. Существование пользователя перед операцией

3. Существование роли ADMIN в базе данных
